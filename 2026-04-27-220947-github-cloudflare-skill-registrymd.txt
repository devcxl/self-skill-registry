  第 6 个问题：审核门禁的阻断策略

  你的 skill-review.yml 中设定了三层状态：

  skills[] 数组

  硬阻断（必须通过才能 merge），还是 软阻断（CI fail 但可以通过 admin override

  ---
  第 15 个问题：用户系统与 Token 管理

  OIDC 登录 + 每人独立 token 意味着需要用户表和 token 表。我的建议：

  D1 新增两张表：

  CREATE TABLE users (
    id TEXT PRIMARY KEY,
    oidc_provider TEXT NOT NULL,      -- 'github' | 'feishu' | 'dingtalk'
    oidc_sub TEXT NOT NULL,           -- OIDC subject identifier
    username TEXT NOT NULL,
    email TEXT,
    created_at TEXT NOT NULL,
    UNIQUE(oidc_provider, oidc_sub)
  );

  CREATE TABLE user_tokens (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    token_hash TEXT NOT NULL,         -- SHA-256 of the token, never store raw 
  token
    name TEXT NOT NULL DEFAULT 'default',
    last_used_at TEXT,
    created_at TEXT NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
  );

  Token 生成时机有两个选择：

  - A. Web UI 首次登录时自动生成：用户用 GitHub OAuth 登录 Web UI →
  系统自动创建一个 token → 用户可在 Web UI "Settings" 页面查看/复制/重新生成
  - B. Web UI 手动创建：用户登录后进入 Settings 页面，手动点 "Create Token"

● 设计文档里 import:registry 只是写了个名字，具体实现没展开。它的实际作用是：

  把 build-registry.ts 生成的 manifest 数据写入 D1。

  具体流程：

  1. build-registry.ts 扫描全部 skills/ 目录，生成 index.json 和每个 skill 的
  manifest JSON（skills/<name>.json）
  2. pack-skills.ts 为每个 skill 打包 tar.gz，计算 sha256，把 sha256 回填到
  manifest
  3. publish:r2 把 tar.gz 上传到 R2
  4. import:registry 读取最终 manifest，对 D1 执行 upsert：

  -- 每个 skill 一行
  INSERT INTO skills (name, description, license, compatibility, ...)
  VALUES (?, ?, ?, ?, ...)
  ON CONFLICT(name) DO UPDATE SET ...;

  -- 每个 version 一行
  INSERT INTO skill_versions (skill_name, version, tarball_key, sha256, ...)
  VALUES (?, ?, ?, ?, ...)
  ON CONFLICT(skill_name, version) DO UPDATE SET ...;

  "全量"的问题是：build-registry.ts 当前设计是扫描全部 skill
  目录，即使只改了一个 skill，也会重新 upsert 全部 400 条。这在 CI
  中当然能跑，但不够精准。

  改进方案：release.yml 不用 build-registry.ts 的全量扫描，而是用 git diff
  只检测 main 上本次 push 实际变更了哪些 skill 目录，只对变更的 skill 做 build +
   pack + upsert。

  但这个优化可以后面做。第一阶段 400 个 skill 批量导入后，日常 PR 修改通常只涉及
   1-3 个 skill，全量扫描 400 个耗时也远低于 1 秒。

  回答你的问题：import:registry 确实是全量 upsert（每个 skill 都 upsert
  一次），这对于 400 个 skill 完全够用，不需要改成增量。
