# Reader Testing 示例

本文件展示 Stage 3（读者测试）的具体执行方式，供 AI 在无 sub-agent 时指导用户操作，或在有 sub-agent 时作为测试 prompt 模板。

---

## 方式一：用户手动测试（无 sub-agent）

在全新 Claude 会话中粘贴以下引导语：

```
我需要你扮演目标读者来测试这份文档。

**文档内容：**
[粘贴完整文档]

**测试方式：**
1. 先通读全文，不要中途停下来
2. 读完后，列出 5-10 个你在读之前就期待回答的问题
3. 对照问题列表，标注哪些答案你找到了，哪些你找不到或觉得模糊
4. 指出任何你发现的前后矛盾或隐含假设

**输出格式：**
- 期待的问题列表
- 每个问题的回答质量（✅ 清晰 / ⚠️ 模糊 / ❌ 未回答）
- 发现的自相矛盾或错误假设
```

---

## 方式二：sub-agent 自动测试（有 fresh sub-agent 时）

给 fresh sub-agent 的 prompt 示例：

```
你是这份文档的目标读者。请阅读以下文档，然后：
1. 列出你作为读者最关心的 5 个问题（读之前就有的问题）
2. 对每个问题，标注你是否能从文档中找到清晰答案
3. 指出文档中任何前后矛盾、隐含假设或表达模糊的地方

不要假设任何文档未明确说明的内容。

--- 文档开始 ---
[粘贴完整文档]
--- 文档结束 ---

输出格式：
| 问题 | 能否回答 | 答案位置/问题描述 |
|---|---|---|
...
```

### 常见失败模式（用于判断测试结果）

| 失败模式 | 说明 | 修复方向 |
|---|---|---|
| 隐含假设未声明 | 作者默认读者知道 X，但读者实际不知道 | 在文档开头补充背景章节或术语定义 |
| 因果链断裂 | 结论跳步，读者无法跟随推理过程 | 增加过渡段落或补充数据来源 |
| 读者类型不匹配 | 写的太浅（专家觉得侮辱）或太深（新手看不懂） | 调整 TL;DR 的一句话结论层级 |
| 约束条件未声明 | 作者知道约束但读者猜不到 | 在 1.3 约束条件节显式列出 |
| 竞品对比缺失 | 只讲自己的方案，不讲为什么不选其他方案 | 在"备选方案"节补充 |

## 方式三：简化自检（时间紧迫时）

如果时间不允许完整 reader testing，至少让用户回答这 3 个问题：

1. **TL;DR 测试**：把这篇文档 TL;DR 那句话念给一个不了解项目的同事听，TA 能复述出核心问题和解决方向吗？
2. **逆向测试**：找一个竞品方案，问"为什么我们不选它"，文档里有答案吗？
3. **边界测试**：找一个最极端的边界情况，问"这种情况怎么处理"，文档里有说明吗？

如果任何一个答案是"没有"，就回到对应章节补充。
