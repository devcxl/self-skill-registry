# 深度分析方法论 (Deep Analysis Methodology)

综合性问题分析与根因排查方法论。适合事故排查、技术复盘、业务分析、质量改进等场景。

## 核心方法论组合

实际工作中最实用的组合：

```
MECE 拆解
+ 假设驱动验证
+ 5 Why 根因分析
+ 风险矩阵排序
+ PDCA 闭环
```

### 1. MECE（Mutually Exclusive, Collectively Exhaustive）
拆解问题，确保不重不漏。

### 2. 5W2H
明确问题背景：
- **What** — 对象
- **Why** — 原因
- **Who** — 对象
- **When** — 时间
- **Where** — 地点
- **How** — 方式
- **How much** — 成本

### 3. 5 Why
从表面现象追到根因，连续追问 5 层"为什么"。

### 4. 鱼骨图（因果图）
从人、机、料、法、环、测等维度排查原因。

### 5. 第一性原理
剥离惯例，从基本事实重新推导。

### 6. 假设驱动分析
先提出可能原因，再通过证据逐个验证。一次只验证一个变量。

### 7. 对比分析
正常与异常、改动前后、不同环境之间进行比较。

### 8. 因果链分析
区分：触发条件 → 直接原因 → 系统缺陷 → 管理根因。

### 9. 风险矩阵
按发生概率 × 影响程度确定优先级。

### 10. PDCA（Plan-Do-Check-Act）
完成分析 → 实施改进 → 验证效果 → 持续修正。

## 通用深度分析 12 步 SOP

### 第一步：定义问题

**输出模板：**
```
问题是什么：
期望结果是什么：
实际结果是什么：
首次发生时间：
影响范围：
分析目标：
```

**要求：** 问题必须可以观察、验证和复现。

### 第二步：划定边界

**输出模板：**
```
分析对象：
时间范围：
系统范围：
业务范围：
已知约束：
不分析内容：
```

**原则：** 避免分析无限扩散。

### 第三步：收集证据

**证据优先级：**
```
原始数据
> 日志与代码
> 配置与操作记录
> 官方文档
> 当事人描述
> 推测
```

**证据表格式：**

| 编号 | 证据 | 来源 | 时间 | 可信度 |
|------|------|------|------|--------|
| #1   | xxx  | xxx  | xxx  | 高/中/低 |

### 第四步：建立时间线

```
正常状态
→ 发生变更
→ 出现异常
→ 告警或用户反馈
→ 采取措施
→ 当前状态
```

**重点：** 检查异常前发生了什么变化。

### 第五步：拆解问题（MECE）

```
业务层
技术层
数据层
配置层
依赖层
环境层
人员与流程层
```

每层继续拆成可验证的小问题。

### 第六步：提出假设

**每个假设的验证模板：**
```
假设：
支持该假设的现象：
可验证方式：
预期验证结果：
实际验证结果：
结论：
```

**原则：** 一次只验证一个变量。

### 第七步：定位直接原因

判断哪个条件直接触发了问题：

```
异常输入
配置错误
代码缺陷
资源不足
依赖故障
时序竞争
权限问题
数据不一致
```

**注：** 直接原因只能解释"为什么这次发生"。

### 第八步：追查根因

连续执行 5 Why：

```
为什么发生？
为什么系统允许它发生？
为什么测试没有发现？
为什么监控没有发现？
为什么流程没有阻止？
```

**根因一般落在：**
- 架构设计
- 边界条件
- 防御机制
- 测试覆盖
- 发布流程
- 权限管理
- 监控告警
- 责任机制

### 第九步：验证因果关系

**至少满足：**
```
时间顺序成立
原因能够解释全部主要现象
移除原因后问题消失
重新引入原因后问题复现
不存在更合理的替代解释
```

**无法完整验证时，标注置信度。**

### 第十步：评估影响和风险

**风险评分：**
```
风险分数 = 发生概率 × 影响程度 × 难以发现程度
```

**分析维度：**
- 受影响用户
- 数据影响
- 业务损失
- 安全风险
- 扩散范围
- 恢复难度
- 再次发生概率

### 第十一步：制定措施

**四类措施：**

| 层级 | 目标 |
|------|------|
| 止损措施 | 立即恢复或限制影响 |
| 修复措施 | 消除直接原因 |
| 预防措施 | 防止同类问题复发 |
| 治理措施 | 改进架构、流程和监控 |

**每项措施必须包含：**
```
负责人
优先级
截止时间
验证标准
回滚方案
```

### 第十二步：验证和复盘

**验证清单：**
- 问题是否消失
- 性能是否恢复
- 是否引入新问题
- 监控是否能发现
- 测试是否覆盖
- 文档是否更新

**最终闭环：**
```
发现问题
→ 分析根因
→ 实施修复
→ 验证结果
→ 固化规则
→ 持续检查
```

## 标准输出模板

```
1. 核心结论
2. 问题定义
3. 影响范围
4. 时间线
5. 事实与证据
6. 假设及验证
7. 直接原因
8. 根本原因
9. 风险评估
10. 解决方案
11. 实施计划
12. 验证标准
13. 遗留问题
14. 防止复发措施
```

## 使用示例

> 使用 deep-analysis-methodology skill 对 [项目/事件] 进行复盘。重点使用 MECE 拆解、5 Why 根因分析和 PDCA 闭环。

### 问题排查提示词

> 使用 deep-analysis-methodology skill 排查 [问题描述]。从定义问题开始，逐步推进到假设驱动验证和根因定位。
