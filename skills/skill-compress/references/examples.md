# Skill 压缩示例

## 示例 1：压缩 description

### 压缩前

```yaml
name: backend-helper
description: 用于处理后端开发中的各种相关工作，包括需求分析、接口设计、代码生成、代码审查、问题排查以及相关文档整理。
```

### 问题
- 职责过宽
- 同时覆盖多个工作流
- 不知道何时不该用

### 压缩后

```yaml
name: generate-spring-module
description: 用于生成 Spring Boot 标准模块骨架。当需要新建符合既定分层规范的模块时触发；不要用于业务逻辑实现、线上排障或架构评审。
```

## 示例 2：压缩正文

### 压缩前

```md
这个 skill 的设计初衷是帮助开发者在复杂项目中快速完成标准化模块建设。由于团队中不同成员对于目录结构、命名规范和模块边界的理解不一致，因此我们希望通过这个 skill 来统一做法。使用时需要先充分理解用户需求，再结合项目背景、模块演进历史、已有代码风格和未来扩展性进行综合考虑……
```

### 问题
- 大量背景叙述
- 可执行信息很少
- 主流程不清楚

### 压缩后

```md
## 作用
生成标准模块骨架。

## 输入
- 模块名
- 包名前缀
- 分层约定

## 执行步骤
1. 校验输入
2. 检查现有目录风格
3. 生成标准目录与基础文件
4. 输出变更说明

## 约束
- 不生成未要求的业务逻辑
- 不新增额外依赖
- 保持现有命名风格
```

## 示例 3：拆分大 skill

### 压缩前

一个 skill 同时提供：
- 需求分析
- 文档生成
- 代码生成
- review
- fix

### 推荐拆分

- `analyze-requirement`
- `write-tech-design`
- `generate-code-skeleton`
- `review-implementation`
- `fix-implementation`

### 拆分原则
- 按工作流拆，不按抽象大类拆
- 每个 skill 保持单一输入输出模式
- description 明确“触发 / 不触发”边界

## 示例 4：把示例外置

### 压缩前

正文中放了 6 个几乎重复的示例，只是语言或技术栈略有差异。

### 压缩后

主文件只保留 1 个代表示例，其他示例迁移到 `references/examples.md`。

### 原则
- 正文保留规则优先
- 示例只用于帮助理解关键规则
- 重复示例默认外置
